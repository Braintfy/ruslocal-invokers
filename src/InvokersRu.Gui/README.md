# InvokersRu GUI

`InvokersRu.Gui.exe` — русскоязычная Windows-оболочка над консольным патчером. Оболочка не содержит собственной логики изменения игровых файлов и не внедряется в процессы игры.

> **Legacy / WIP:** эта оболочка всё ещё подключена к старому заблокированному `StreamingAssets`-потоку. Отдельный CLI runtime-cache тест успешно загрузил русский preview из `LocalLow`, но GUI ещё не переведён на команды `cache-plan`, `cache-apply` и `cache-restore`. Кнопка установки здесь намеренно отключена; эту сборку нельзя выдавать за рабочий русификатор или включать в публичный релиз.

## Файлы рядом с GUI

- `InvokersRu.Gui.exe` — интерфейс;
- `InvokersRu.Cli.exe` — write-enabled CLI с вшитым доверенным манифестом совместимости;
- `ru_RU.mvp.jsonl` — зафиксированный каталог перевода для последующего теста после выяснения поведения загрузчика.

Подмена или отсутствие любого обязательного файла приводит к безопасному отказу CLI. GUI не принимает произвольный файл перевода и не имеет режима `force`.

## Поведение

1. Путь к игре определяется автоматически: `%APPDATA%\zone.hitzone.invokers.launcher\game`.
2. При запуске и перед каждой операцией выполняется `InvokersRu.Cli.exe plan --game-root <путь>`.
3. Даже при точном ответе `CompatibleOriginal` + `READY_TO_APPLY` GUI сообщает, что пакет пока не принят загрузчиком, и не позволяет установить его.
4. Неизвестная версия, несовпадение хэшей, незавершённая транзакция и непроверенная сборка блокируют запись с предупреждением о риске некорректного перевода.
5. Единственная оставленная операция записи в GUI — `restore --acknowledge-risk I_ACCEPT_LOCAL_MODIFICATION`, и она доступна только для точного состояния `PatchedByThisTool`, созданного ранее этим патчером, при закрытых процессах игры и лаунчера.

Процессы запускаются через `ProcessStartInfo.ArgumentList`, с `UseShellExecute=false`, перенаправлением stdout/stderr и без консольного окна. GUI не запускает игру, не завершает её процессы и не работает с сетью. В текущей сборке нет вызова команды `apply`.

## Сборка

```powershell
dotnet build .\src\InvokersRu.Gui\InvokersRu.Gui.csproj -c Release
```

Для готового каталога используйте `publish.ps1`. Ему нужен уже опубликованный supervised CLI, чтобы GUI не мог случайно получить обычную dev-сборку без разрешённых операций:

```powershell
.\src\InvokersRu.Gui\publish.ps1 `
  -CliPublishedDirectory .\work\publish\0.2.0-supervised-preview-win-x64 `
  -Translations .\work\mvp\Prod_0.60.0_26\overlay-through-0020-sol10.jsonl `
  -OutputDirectory .\work\publish\0.2.0-gui-win-x64
```

Скрипт создаёт только новый каталог, проверяет метаданные доверенного манифеста CLI и выполняет read-only `help`/`plan` на пустом каталоге внутри временного publish-каталога. Команды `apply` и `restore` при публикации не запускаются. Выход предназначен для закрытого диагностического/восстановительного теста, а не для публичного релиза локализации.
