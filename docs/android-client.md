# Android-клиент: результаты разведки

Разведка 20 августа 2026 года. Проверено на живом устройстве Samsung Galaxy S25 (SM-S931B, Android 16) с установленной игрой версии `0.60.1247`, плюс разбор дистрибутива `Invokers: Titan Legacy 0.60.1247` (XAPK, 835 МБ).

## Главный вывод

Русификатор для Android **возможен**, готовый перевод переиспользуется **целиком и без изменений**, а собранный для macOS файл подходит Android **побайтово**. Рабочая форма — утилита с компьютера через ADB; приложением на самом телефоне обойтись нельзя.

## Как устроен дистрибутив

Android App Bundle из трёх частей:

| часть | размер | что внутри |
| --- | --- | --- |
| `hitzone.anima.spirit.guardians.apk` | 46 МБ | база, IL2CPP-метаданные |
| `UnityDataAssetPack.apk` | 734 МБ | Unity-данные, в том числе `assets/i18n/` |
| `config.arm64_v8a.apk` | 55 МБ | нативные библиотеки |

Package name совпадает с iOS bundle id: `hitzone.anima.spirit.guardians`. Встроенные `assets/i18n/*.bin.br` (14 языков) **побайтово идентичны** тем, что лежат в iOS-бандле, — совпадают SHA-256 и `en_US.bin.br`, и `uk_UA.bin.br`, и `manifest.dat`.

## Эмуляторы (BlueStacks и подобные)

Эмулятор — это тот же Android, только на самом компьютере, поэтому маршрут через ADB работает без изменений и оказывается короче всех остальных: нет кабеля, драйверов, кода сопряжения и окна «Разрешить отладку» на чужом экране. Помощник перебирает локальные порты (`5555`, `5556`, `5565`, `5575`, `5585`, `5595`, `62001`, `62025`, `21503`, `5554`) и на Windows дополнительно читает `%ProgramData%\BlueStacks_nxt\bluestacks.conf`, где BlueStacks хранит порт каждого экземпляра.

**Что пришлось починить, чтобы это заработало.** Проверка прав требовала членства shell в группе `ext_data_rw`. Группа появилась вместе со scoped storage, а эмуляторы обычно живут на более старом Android, где её нет и не должно быть, — и устройство отсекалось на входе, хотя shell писал в каталог игры без единой помехи. Теперь проверяется не группа, а сама возможность: создать и удалить пробный файл в каталоге. Это верный вопрос на любом Android и по-прежнему ловит корпоративные политики, защищённую папку и клоны приложений, ради которых проверка и была.

С включённым в эмуляторе root компьютер вообще не нужен: APK ставится перетаскиванием на окно эмулятора и работает сам, как на телефоне с root.

Проверено на подставном устройстве, воспроизводящем ответы эмулятора (Android без `ext_data_rw`, adb на `127.0.0.1:5555`): подключение, проверка доступа и полный цикл действия проходят. На живом BlueStacks не тестировалось.

## Где лежит рантайм-кэш

```text
/sdcard/Android/data/hitzone.anima.spirit.guardians/files/i18n/
```

Это **внешний** каталог приложения, а не внутренний `/data/user/0/...`, — принципиально важно: сюда ADB имеет доступ, туда бы не имел.

Состав после выбора украинского языка полностью совпадает с macOS:

```text
dl_en_US.bin        7 729 709
dl_en_US.bin.ver            9   -> "0.60.1247"
dl_uk_UA.bin       11 642 408
dl_uk_UA.bin.ver            9   -> "0.60.1247"
en_US.bin           7 729 404
en_US.bin.src
```

Файлы `dl_en_US.bin` и `dl_uk_UA.bin` **побайтово равны** снятым с macOS-клиента той же версии: тот же `Prod_0.60.0_68`, 41 292 записи, `locale_id` 8. Поэтому собранный для macOS русский файл ставится на Android без пересборки.

### Устаревший формат в версии 0.59

В сборке `0.59.1005` тот же каталог содержал единственный файл `cache.dat2` (8,9 МБ) с магией `AMNA` — контейнер с **текстовыми** ключами вместо хэшей. В `0.60.1247` игра перешла на тот же LOC1, что на других платформах; `cache.dat2` остаётся лежать как мусор от прошлой версии и больше не используется. Отдельный парсер под него не нужен.

## Ключевая находка: хэш-функция LOC1

Ключ записи LOC1 — это **FNV-1a 64-bit от UTF-8-представления строкового ключа локализации**.

```python
def loc1_key_hash(key: str) -> int:
    h = 0xCBF29CE484222325
    for byte in key.encode("utf-8"):
        h = ((h ^ byte) * 0x100000001B3) & 0xFFFFFFFFFFFFFFFF
    return h
```

Проверено сопоставлением строковых ключей из IL2CPP-метаданных APK со значениями в `dl_en_US.bin`:

```text
ui-multibattle-exit-popup-title                  -> "Stop Multi-Battle?"
ui-multibattle-result-claim-reward-button-label  -> "CLAIM REWARDS"
ui-player-profile-avatar-frame-unlock-vip-level  -> "Unlocks at VIP Pass Level {0}"
```

Раньше проект работал с хэшами как с непрозрачными идентификаторами. Теперь по хэшу можно восстановить осмысленное имя строки, что даёт контекст для перевода и для экранного QA: по префиксу ключа видно, к какому экрану строка относится.

## Почему нельзя сделать приложением

- С Android 11 обычному приложению закрыт доступ к `Android/data` чужого пакета: `ACTION_OPEN_DOCUMENT_TREE` для этого каталога запрещён, а разрешение `MANAGE_EXTERNAL_STORAGE` его не открывает.
- Внутренний `/data/user/0/<пакет>` закрыт изоляцией по UID; `run-as` работает только для отладочных сборок, а игра собрана в релизе — проверено, отказывает.
- Обход через Shizuku существует, но требует отдельного приложения, права слетают после перезагрузки, и правила Google Play такое не пропускают. Приложение вместо этого собирает файл само, а доступ к каталогу игры берёт на себя компьютер — см. ниже.
- Пересборка APK игры отпадает: ломается подпись, теряются обновления, и это раздача игры целиком, чего проект не делает.

## Почему работает через ADB

`adb shell` работает от пользователя `shell`, которому демон намеренно выдаёт группы `ext_data_rw` и `ext_obb_rw` — именно ради доступа к `Android/data`. На тестовом устройстве проверены все нужные операции:

```text
uid=2000(shell) ... groups=... ,1078(ext_data_rw),1079(ext_obb_rw), ...
push OK, чтение OK, mv OK, rm OK
```

`mv` проверялся отдельно: на части свежих прошивок (сообщения про Pixel с Android 16 QPR2) переименование внутри `Android/data` от имени shell не работает. Поэтому утилита должна проверять доступные операции и деградировать, а не считать их данностью. Первым шагом разумно смотреть `adb shell id` на наличие группы `ext_data_rw`.

## Как это устроено сейчас: телефон собирает, компьютер передаёт

Русский файл нельзя собрать нигде, кроме как из двух файлов игры — английского и украинского. Компьютер до них дотягивается, приложение на телефоне без root — нет. Но собрать файл приложение умеет: контейнер LOC1 и чтение каталога переписаны на Java.

Отсюда разделение обязанностей: **компьютер — курьер, телефон — сборщик**.

Обмен идёт через каталог самого патчера, единственное место, куда adb пишет, а приложение читает без каких-либо разрешений:

```text
/sdcard/Android/data/ru.invokers.patcher/files/bridge/
    in/dl_en_US.bin      кладёт компьютер
    in/dl_uk_UA.bin      кладёт компьютер (оригинал из резервной копии)
    in/ru_RU.jsonl       кладёт компьютер
    out/dl_uk_UA.bin     пишет приложение
    out/status.txt       пишет приложение: «OK 41037» или «ERR текст»
```

Компьютер запускает сборку явным интентом и ждёт метку:

```sh
adb shell am start -n ru.invokers.patcher/.MainActivity -a ru.invokers.patcher.BRIDGE
```

`status.txt` пишется последним и только после самого файла, поэтому увидеть `OK` и получить недописанный файл нельзя. Приложение при старте будит экран и держит его включённым: работа идёт в activity, а уснувший телефон её остановил бы.

Такое разделение убирает с компьютера всё, кроме adb. Ему не нужны ни .NET, ни сам проект — помощник `pc/install-android.sh` и `pc/install-android.ps1` при первом запуске сам скачивает platform-tools с сайта Google.

### Три пути для игрока

| Путь | Что нужно | Кто собирает |
| --- | --- | --- |
| Только телефон | root | приложение, целиком само |
| Компьютер по Wi-Fi | «Отладка по Wi-Fi» и код сопряжения | приложение, компьютер передаёт |
| Компьютер по кабелю | «Отладка по USB» | приложение, компьютер передаёт |

Без root четвёртого пути нет, и приложение говорит об этом прямо на первом экране, а не падает с непонятной ошибкой.

### Сборка на Java равна сборке на .NET

Собранный телефоном файл разбирается в те же 41 292 записи с теми же значениями, что и файл, собранный `InvokersRu.Cli`. Побайтово они различаются: строки укладываются в пул в разном порядке, а смещения хранятся явно, поэтому на игру это не влияет.

Одна деталь стоила отдельной отладки: `String.format("%02X", …)` на 2,6 млн вызовов превращал сборку на телефоне в минуты. С ручной шестнадцатеричной записью и одним проходом вместо трёх — 2 секунды.

## Ручная установка для разработки

```sh
PKG=hitzone.anima.spirit.guardians
DIR=/sdcard/Android/data/$PKG/files/i18n

adb pull $DIR/dl_en_US.bin .
adb pull $DIR/dl_uk_UA.bin .

InvokersRu.Cli build --english dl_en_US.bin --base dl_uk_UA.bin \
  --translations translations/ru_RU.jsonl --output dl_uk_UA.ru.bin \
  --include-draft --raw --per-locale-content-version

adb shell am force-stop $PKG
adb push dl_uk_UA.ru.bin $DIR/dl_uk_UA.bin
adb shell sha256sum $DIR/dl_uk_UA.bin      # сверить с локальным
```

То же самое одной командой делает `scripts/android-patch.sh` с действиями `status`, `apply`, `restore` и `reset`.

### Почему `reset` удаляет ещё и метку версии

Удалить `dl_uk_UA.bin` мало: `dl_uk_UA.bin.ver` продолжает утверждать, что кэш актуален, и клиент молча откатывается на копию внутри своего пакета вместо загрузки с сервера. Удаляются оба файла — тогда игра скачивает чистый оригинал.

### Владелец файла отличает оригинал от подменённого

Игра пишет свои файлы от собственного пользователя (`u0_a350`), всё принесённое через adb — от `shell`. Без этой проверки повторный запуск записал бы уже пропатченный файл как «оригинал», и откат навсегда потерял бы украинский текст.

## Ограничения

- Тексты, которые приходят с сервера под выбранную локаль — витрина магазина, акции, события — в файле локализации отсутствуют и остаются украинскими. Проверено: строк вида «НАБІР ВЕЛ.САМОЦВІТІВ» в собранном LOC1 нет ни в каком виде.
- Язык в игре должен оставаться украинским. Как и на других платформах, выбор языка в настройках заставляет клиент заново скачать файл и стирает перевод.
- Обновление игры сбрасывает перевод: нужно ставить заново.
- Samsung Auto Blocker (включён по умолчанию с One UI 6.1.1) блокирует ADB по USB, его нужно отключить. Xiaomi/HyperOS требует отдельный тумблер «Отладка по USB (настройки безопасности)».
- Если игра установлена в защищённой папке, рабочем профиле или клоне приложения, путь уходит в `/storage/emulated/<id>/`, куда `shell` не попадёт.
- На корпоративных устройствах политика `DISALLOW_USB_FILE_TRANSFER` отключает сценарий целиком.
