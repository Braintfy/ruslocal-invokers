# ПК-клиент: инструмент перевода

Версия для игры, установленной на сам компьютер. Собирается скриптом
`scripts/build-pc-game-tool.sh` в архив `Rusifikator-Invokers-PC-Game.zip` (37 МБ).

Не путать с `Rusifikator-Invokers-PC.zip` — тот помощник ставит перевод **на телефон**
и к игре на компьютере отношения не имеет.

## Что внутри архива

| Файл | Зачем |
| --- | --- |
| `InvokersRu.Cli.exe` | self-contained win-x64, собирает русский файл из файлов игры и каталога |
| `ru_RU.jsonl` | каталог перевода, 35 МБ |
| `install-pc.ps1` | драйвер: находит игру, делает копию оригинала, собирает, заменяет |
| `Русификатор-ПК.cmd` | обёртка, чтобы запускать двойным кликом |
| `ПРОЧТИ-МЕНЯ-ПК.txt` | инструкция игроку |

Каталог лежит **внутри архива**, а не качается при каждом запуске. Это главное отличие
от macOS-приложения, и оно намеренное: 35 МБ по обычному HTTP — самое ненадёжное звено
всего процесса. При тестировании `Invoke-WebRequest` обрывался на 22 КБ из 35 МБ
(`The response ended prematurely`), а `curl` к `api.github.com` падал с `SSL_ERROR_SYSCALL`.
Инструмент всё равно пытается взять свежий каталог, но встроенный — это пол, а не потолок.

## Как устроена замена

Тот же приём, что на macOS: `cache-apply` в CLI закрыт мутационным гейтом и требует
сертифицированного профиля, поэтому драйвер им не пользуется. CLI только **собирает**
байты командой `build` в отдельный файл, а подстановку делает скрипт — во временный файл
рядом с целью, со сверкой SHA-256, затем `Move-Item -Force`.

```
InvokersRu.Cli.exe build --english dl_en_US.bin --base dl_uk_UA.bin \
    --translations ru_RU.jsonl --output <временный> --report <report.json> \
    --include-draft --raw --per-locale-content-version
```

Поиск каталога игры идёт по наличию `dl_en_US.bin`, а не по жёсткому пути: перебираются
`%USERPROFILE%\AppData\LocalLow\<студия>\<продукт>\i18n` и `%LOCALAPPDATA%Low\...`.
Переименование студии в новой версии игры это переживёт. Ноль совпадений, одно и несколько —
три разных сообщения; угадывать при нескольких скрипт отказывается.

Оригинал кладётся в `%LOCALAPPDATA%\InvokersRu\backup\original-<SHA>.bin`, то есть переживает
удаление архива. Копия снимается только пока в каталоге лежит собственный файл игры: если
там уже перевод, `state.txt` это помнит и оригинал не затирается патченым.

## Что проверено и чем

Прогон делался на macOS под portable PowerShell 7.5.4, с маковским срезом CLI и подставным
каталогом игры из настоящих файлов клиента.

- **Сборка win-x64 кроссплатформенно собирается** с macOS: 37 665 376 байт, `PE32+ executable
  (console) x86-64`. Скрипт сборки проверяет это и падает, если получился не Windows-бинарь.
- **Результат совпадает с macOS-сборкой побайтово.** Из нетронутого `dl_uk_UA.bin`
  (`D32B0381…`) драйвер собрал файл с SHA-256 `4E3AC2FB…` — ровно тот, что ставит на этой же
  машине маковский патчер. Это сильнее любого функционального теста: две независимые реализации
  драйвера сошлись на одном байте.
- **Откат возвращает точный оригинал** — `D32B0381…` после `-Action restore`.
- **Повторная установка идемпотентна**: перевод уже стоит → оригинал не перезаписывается,
  в хранилище остаётся одна копия.
- **Автопоиск каталога**: подставная структура `AppData\LocalLow\Hit_Zone\Invokers\i18n`
  находится; при двух каталогах скрипт отказывается угадывать; при отсутствии игры выдаёт
  сообщение про «не установлена или ни разу не запускалась», а не про доступ к файлам.
- **Запасной каталог сработал по-настоящему**: загрузка упала в обоих прогонах, и перевод
  был взят из архива — то есть тот самый сценарий, ради которого каталог и вложен.

Один дефект тестами и найден: CLI отказывается перезаписывать `report.json`, а драйвер удалял
перед сборкой только собранный файл. Второй запуск подряд падал с «не удалось собрать перевод»
и ничем это не объяснял. Исправлено.

## Что НЕ проверено — для сессии на ПК с игрой

Ни одной машины с ПК-версией игры под рукой не было, поэтому три вещи остаются гипотезами.

1. **Реальный путь к данным.** `RuntimeCacheService` пинит
   `%USERPROFILE%\AppData\LocalLow\Hit_Zone\Invokers\i18n`, но это значение из профиля версии
   `0.60.1239`, а актуальная — `0.60.1247`. Проверить: существует ли каталог и лежат ли там
   `dl_en_US.bin` и `dl_uk_UA.bin` после того, как в игре был выбран украинский.

2. **Совместимость файлов ПК-версии.** Для Android доказано, что файлы локализации побайтово
   равны маковским. Для ПК такого доказательства нет, а профиль в репозитории описывает старую
   версию с другим `content_version` (`Prod_0.60.0_57` против `_68` на маке) и другим числом
   записей (41 290 против 41 292). Проверить командой `inspect` — см. ниже.

3. **Поведение под настоящим Windows PowerShell 5.1.** Тестировалось на pwsh 7.5.4. В скрипте
   намеренно нет ничего из PowerShell 7 (`??`, тернарники, `-Parallel`), но `Get-Content -Tail`
   и `ConvertFrom-Json` на 5.1 стоит увидеть своими глазами.

### Порядок проверки на ПК

```powershell
# 1. Есть ли данные и что в них
dir "$env:USERPROFILE\AppData\LocalLow\Hit_Zone\Invokers\i18n"
.\InvokersRu.Cli.exe inspect "$env:USERPROFILE\AppData\LocalLow\Hit_Zone\Invokers\i18n\dl_en_US.bin"
.\InvokersRu.Cli.exe inspect "$env:USERPROFILE\AppData\LocalLow\Hit_Zone\Invokers\i18n\dl_uk_UA.bin"
```

Сверить с маковскими значениями: `content_guid` `ad875e27-1bf6-4f4a-8ed5-3957d0ed05fa`,
`schema` 4, `locale_id` 1 для английского и 8 для украинского. Если `content_version`
отличается от `Prod_0.60.0_68` — версии игры разошлись, и часть строк уйдёт в английский
fallback; это не поломка, но число в отчёте будет меньше 41 037.

```powershell
# 2. Пробный прогон без замены: собрать во временный файл и посмотреть отчёт
.\InvokersRu.Cli.exe build --english <EN> --base <UK> --translations ru_RU.jsonl `
    --output "$env:TEMP\probe.bin" --report "$env:TEMP\probe.json" `
    --include-draft --raw --per-locale-content-version
type "$env:TEMP\probe.json"
```

Строка `Applied RU:` должна дать 41 037 при совпадающей версии. Игру при этом ничего не трогает.

```powershell
# 3. Полный цикл
.\Русификатор-ПК.cmd        # пункт 1, затем проверить текст в игре, затем пункт 2
```

Если всё сходится — снять этот раздел и заменить его результатами, как сделано
в [android-client.md](android-client.md).

## Ограничения

Мутационный путь CLI (`cache-apply`) здесь не задействован, поэтому проверок NTFS-тома,
reparse-point и сертифицированного профиля в этом сценарии нет. Гарантии дают три вещи
попроще: файл собирается отдельно и сверяется по SHA-256 до подстановки, замена атомарна,
оригинал сохраняется вне архива с содержимым, адресуемым по хэшу.

Перевод стирается, если в игре открыть выбор языка: клиент перекачивает языковой файл
с сервера. Это же и запасной способ вернуть оригинал, когда резервной копии нет.
