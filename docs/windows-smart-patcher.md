# Умный ПК-патчер InvokersRu

Новая Windows-версия заменяет прототип `pc/install-pc.ps1`. Публичный пакет не должен запускать PowerShell/CMD, искать произвольные файлы игры или устанавливать перевод на неизвестную версию.

## Поведение для игрока

При запуске оболочка автоматически:

1. находит runtime-кэш Invokers в профиле текущего пользователя;
2. читает версию и структуру EN/UK LOC1;
3. сверяет точные SHA-256 со встроенным профилем;
4. проверяет состояние предыдущей установки и резервной копии;
5. показывает количество русских и оставшихся английских строк;
6. ищет запущенные процессы игры, лаунчера, updater и crash handler;
7. только после всех проверок включает подходящую кнопку: «Установить», «Обновить русификацию», «Восстановить оригинал» или «Восстановить после сбоя».

Принудительной установки (`Force`) нет. Неизвестная версия всегда остаётся без изменений и получает понятное сообщение о том, что старый перевод может не покрывать новые строки.

## Текущий профиль Windows

- игра: `0.60.1247`;
- контент: `Prod_0.60.0_68`;
- записей LOC1: `41 292`;
- русских строк: `41 037`;
- английский fallback: `1`;
- пустые/служебные строки из базового пакета: `254`;
- каталог: `CBF5211BDCB8E940829F305154CE9A92C0D202BCC6B49617A4B92BA25166600C`;
- ожидаемый итоговый LOC1: `4E3AC2FBF663DA1D3EBF4B2EAEBFAADF5BC2A80AE7E424463582919F07B644CD`.

Каталог является предварительным переводом сообщества. Механическая целостность проверена, но часть формулировок ещё проходит редактуру. Этот факт показывается перед установкой и не маскируется термином «официальный перевод».

## Запись и восстановление

GUI сам не изменяет игру. Он вызывает соседний CLI с профилем, встроенным при release-сборке. CLI передаёт операцию в `RuntimeCacheService`:

- фиксированный путь `LocalLow/Hit_Zone/Invokers/i18n`;
- compile-time capability для release-сборки;
- запрет ссылок/reparse points и неподдерживаемой файловой системы;
- mutex и lock-файл против второго экземпляра;
- immutable content-addressed backup;
- временный файл на том же томе;
- журнал фаз с восстановлением после сбоя;
- повторная проверка EN/UK/stamp и процессов прямо перед commit;
- атомарная замена с сохранением фактически вытесненного файла;
- проверка итогового SHA-256 после commit.

Если официальный updater заменил старую русификацию новым оригинальным файлом, состояние прошлого профиля переносится в `history/superseded`, старый backup сохраняется, а установка разрешается только при точном совпадении нового профиля.

## Обновления через GitHub

`raw/main` не является доверенным источником. Планируемый release-канал использует:

1. изменяемый URL только для небольшого подписанного envelope;
2. ECDSA P-256/SHA-256 и публичный ключ, встроенный в патчер;
3. монотонный `sequence`, срок действия и защиту от отката;
4. неизменяемый артефакт GitHub Release с размером и SHA-256;
5. точные профили версии игры и ожидаемого результата;
6. last-known-good только после успешной проверки и установки.

Если версия патчера ниже `minimum_version`, установка удалённого каталога блокируется и игрок получает ссылку на новый installer. Если патчер просто не последний, показывается предупреждение. При отсутствии сети можно использовать только ранее проверенный совместимый пакет или встроенную версию.

## Defender и SmartScreen

Нельзя честно гарантировать отсутствие предупреждения для нового неподписанного EXE. Для минимизации ложных срабатываний публичный пакет должен:

- обходиться без PowerShell/CMD, injection, hooks, process killing, служб и прав администратора;
- состоять из обычных self-contained файлов .NET без UPX и single-file compression;
- не скачивать и не запускать EXE автоматически;
- быть собран из точного тега в Windows CI;
- подписывать GUI, CLI, uninstaller и installer одной Authenticode-личностью с RFC 3161 timestamp;
- публиковать SHA-256, SBOM и provenance.

До появления доверенной подписи локальные тестовые сборки явно считаются неподписанными preview.
